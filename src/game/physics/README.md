# Physics

`createPhysics()` in `engine.js` creates an independent simulation instance. It owns collision resolution, friction, rolling, shot simulation, action generation and state evaluation. It imports pen data and validated simulation defaults from `src/config`, and runs without React, Three.js or a browser.

`src/game/engine.js` adds the AI strategies to this interface. The renderer reads table dimensions and pen properties from the engine. Keep random seeds explicit in regression tests, avoid mutating input snapshots during a shot, and preserve the knock-off-only win condition.

`src/config/physics.ts` owns gravity, speed/spin/surge strength, integration step and shot duration. `settings.ts` owns default friction/realism; `pens.ts` owns per-model properties. User settings may update an engine's friction/realism after creation. Desk dimensions and collision tolerances remain internal invariants. Recorded samples carry actual timestamps; playback supports nonuniform intervals and repeated final timestamps.

Desk overlap and balance are separate: `overlapsTable` tests the capsule footprint, while `hasTableSupport` requires its uniform centre of mass to remain over the tabletop. Once the centre crosses an edge, the pen is out even if its tail still overlaps the desk. An overlapping pen rotates about the nearest edge/corner under gravity; its inboard end rises while the outboard end lowers, then it drops beside the desk. A fully departed pen falls directly. Both realism modes use this rule.

Recorded samples include the tipping normal, angle, pivot and distance, plus exact support-loss, side-clearance and landing boundaries. Playback reconstructs the pivot arc rather than interpolating a straight chord through wood. Recorded shots finish airborne falls before ending, within the requested simulation time limit. Rendering consumes the recorded orientation rather than deriving a separate tilt from playback time, so settled displays and replay agree. A cached convex cross-section of the original pen geometry sets its resting height as caps and clips roll, without changing model proportions or walking every mesh vertex each frame. The playing hand releases its contact target before playback. Landing sounds use the actual recorded landing event; older recordings retain the legacy timing fallback.

Shots resolve all remaining tabletop motion after the first fall; `afterOut` only adds animation time. `out` is `-1` for no fall, `0`/`1` for that fallen pen, and `2` when both fall during the shot, regardless of order. `outcome.js` maps this to per-player points: both fall means `[1, 1]`. Playable matches and headless rounds share this rule. A shared round advances normally; equal scores at the match goal produce a drawn match.

Run `tests/engine.test.js`, `tests/edge-fall.test.js`, `tests/knockoff.test.js`, `tests/playback.test.js`, and the configuration boundary tests. The edge-fall suite exercises all models, all edges/corners, parallel barrels, resting/sliding/spinning cases, input immutability and matching AI/gameplay outcomes. Actual mesh triangles are checked against the desk throughout interpolated falls. Controller coverage verifies immediate hand release, a completed fall, one score and one landing sound. Native Node scripts do not load `.env.local` automatically. See the [configuration guide](../../config/README.md) and [test matrix](../../../docs/testing.md).
